# Changelog: GitHub panel

## Unreleased

Brings the panel up to date with [herdr-github](https://github.com/luongnv89/herdr-github)'s unreleased changes after 0.4.0 ([luongnv89/herdr-github#18](https://github.com/luongnv89/herdr-github/issues/18), [#20](https://github.com/luongnv89/herdr-github/issues/20), [#25](https://github.com/luongnv89/herdr-github/issues/25)).

### Added

- A setting to choose whether merging a pull request deletes its branch ([#39](https://github.com/luongnv89/rex-extensions/issues/39)). The profiles view has a **Merge mode** row under the prompt rows: **Merge and delete branch**, the default, or **Merge and keep branch**; `e`, enter or its **Change** button switches it, and it's kept in `~/.local/state/rex-github/merge`, so it stays after a restart. In the mode that deletes, once GitHub says the pull request merged, the panel deletes its branch on GitHub with `gh api -X DELETE`, never the local branch or your checkout. It keeps a fork's branch, the branch merged into and the repo's default branch, and says why; in a repo that deletes merged branches itself, it leaves that to GitHub. A branch already gone counts as deleted, and a delete that fails is said in red without undoing the merge. On GitLab, `glab mr merge` gets `--remove-source-branch`. A merge that fails, waits for checks or a queue, or can't be read deletes nothing. The Merge question now names the mode, as in `(squash, then delete its branch)`.
- A key for every button, so the panel works without a mouse ([#37](https://github.com/luongnv89/rex-extensions/issues/37)). `m` presses the selected pull request's **Merge #N** and `c` the selected issue's **Close #N**; both still ask first, and `y` confirms, at once rather than after the 0.4 seconds a second click waits. Pressing `m` or `c` again leaves the question as it is, so a key held down never merges or closes, and any other key still takes the question back. `c` does nothing in Auto-pilot mode, where Close steps aside. In the prompt editor, ctrl-r is **Use default** while you have a custom prompt. `?` lists every key of the view you're in (the lists, Auto-pilot, the profile menu or the profiles), and `?`, esc, `q` or a click closes the list; no other key reaches the view under it. The key hints now say `? keys`, early enough to stay in view in a 36-column pane, and a wide pane also names `m merge #N` or `c close #N` for the selected row. Auto-pilot's narrowest key hints end with a bare `?`. The Merge and Close notices now name `y`. In typing fields `?` is still text.
- Labels on the header's buttons. They now sit on a line of their own under the repo's name, as **☑ Auto-pilot**, **⚙ Profiles**, **↻ Refresh** and **↗ GitHub** (or **↗ GitLab**), and a click on a label presses its button. In a narrower pane the labels drop from the right, leaving those buttons' icons. In a pane too narrow for even the first label, or shorter than 12 lines, the header is one line again, with the bare icons after the repo's name as before.
- Choose a model for an OpenCode profile. OpenCode's interactive command has no `--model` flag, so with a model the panel starts it as `env OPENCODE_CONFIG_CONTENT={"model":"M"} opencode --standalone --prompt <prompt>`: the model goes in a one-line OpenCode config, and `--standalone` gives that pane OpenCode's own server, since the background service doesn't read the variable. Its sessions are still listed with the others. Without a model, OpenCode starts as before. The extension ships no OpenCode models: `+` on **Model** adds yours, as `provider/model` from `opencode models`. The notice now says OpenCode ignores only a thinking level. A panel from before this shows a profiles file with OpenCode models read only.
- Auto-pilot several issues at once ([#31](https://github.com/luongnv89/rex-extensions/issues/31)). On GitHub's issues, a `☑` button in the header, before `⚙`, or `p`, enters Auto-pilot mode: every issue row shows a checkbox in place of its icon, and its Resolve and Close buttons step aside. A click on a row, or space or `x` on the selected one, checks or unchecks it. The key hints give way to a **▶ Start** and **✕ Cancel** bar, shown only in the mode: Start is dimmed and does nothing until an issue is checked, then reads **▶ Start N**. Start, or enter, runs one agent, in one new pane labelled `autopilot-12-15`, on exactly the checked issues, in the list's order: by default the IDD `auto-pilot` skill, as `/auto-pilot --issues 12,15` (`/idd:auto-pilot` from the plugin) for Claude Code and "Use the auto-pilot skill with --issues 12,15." for other agents, with the profile Resolve starts (the profile menu opens first when you have profiles of your own). Once the agent runs, the mode ends and nothing is checked; Cancel, `☑`, `p`, esc and `q` leave it too, without closing the panel, as do the pull requests list and another repo, with a notice saying how many issues that unchecked. The bar's key hints start with `⏎ start`; in a narrow pane they shorten to `⏎▶ · ␣☑ · q✕`, so a 36-column pane still shows the keys that start, check and cancel. An issue that leaves the list is unchecked. Like Resolve and Review, Auto-pilot can send a prompt of your own, set in the profiles view's new **Auto-pilot prompt** row, with `{numbers}` where the checked issues' numbers go (`12,15`); one longer than 500 characters with them filled in is refused before anything runs. A custom Auto-pilot prompt is kept in the profiles file as version 4, written only while you have one, so a file without stays version 1, 2 or 3, byte for byte; a panel or herdr-github from before version 4 shows such a file read only.
- Start Resolve or Review from the keyboard alone, as on a phone over remote access, where taps on the buttons may not reach the panel ([#28](https://github.com/luongnv89/rex-extensions/issues/28)). The menu of profiles `a` opens now sits at the bottom of the panel, just above the notice and the key hints, so it's in view on a phone, which shows only the bottom of the pane; a click on a row's button still opens it under that button. The key hints start with what `a` acts on, such as `a resolve #12` or `a review #34`, so it survives a narrow pane's cut, and the menu's hints name `j`/`k` and `q` as well as the arrows and esc, with a shorter form that keeps a key that cancels in view. With only the built-in profile, `a` still starts it at once.
- A **Close #N** button on every issue row, on GitHub and GitLab, to close an issue without resolving it ([#27](https://github.com/luongnv89/rex-extensions/issues/27)). On GitHub it sits next to the Resolve button (on a line of its own in a narrow pane); on GitLab it's on a line of its own. Like Merge, the first press only asks: the button turns red and reads **Confirm close #N**; a second press closes that issue, and only that one, with `gh issue close` or `glab issue close`, and starts no agent or pull request. Any other key or click, including esc and `q`, takes the question back, and a second press within 0.4 seconds of the first only keeps the question. While the close runs the button reads **Closing #N…**; `Closed #N` takes the issue out of the list, and a refresh already running doesn't bring it back; a refused close shows the CLI's reason in red and keeps the issue.
- Choose a profile's model from a list ([#24](https://github.com/luongnv89/rex-extensions/issues/24)). In the profile form, **Model** is now a choice: ←/→ or space step through **harness default**, then the models the extension ships for the selected harness (Claude Code via `mcc run`, Claude Code, Codex, Pi and Mistral Vibe; none for OpenCode), then the ones you added. `+` on **Model** adds a model that isn't listed, checked by the same rule as before, and `-` removes one you added. Added models are kept per harness in the profiles file as version 3 (`customModels`), written only while you have one, so a file without stays version 1 or 2; a panel or herdr-github from before version 3 shows such a file read only. A profile whose model is in neither list loads, shows and starts as before.
- A **Mistral Vibe** harness for agent profiles. Resolve and Review start `vibe <prompt>` in the new pane. A model on the profile goes in the `VIBE_ACTIVE_MODEL` environment variable, as `env VIBE_ACTIVE_MODEL=M vibe <prompt>`, since Vibe's `--model` flag works only in headless mode; an alias Vibe doesn't know starts its default model. A Mistral Vibe profile takes no thinking level: Vibe sets it per model in its own config. The panel also recognises a pane running Vibe, whose program is `vibe-rs`, as your agent, and opens the new pane beside it. herdr-github gets the same harness; a herdr-github without it shows a profiles file with a Mistral Vibe profile read only.
- A **Resolve #N** button under every issue and a **Review #N** button under every pull request, on GitHub. Each acts on its own row; `a` acts on the selected one. There are no Resolve or Review buttons on GitLab, since both skills work through `gh`.
- A **Merge #N** button on every pull request row, next to its Review button (on a line of its own in a narrow pane), and a **Merge !N** button on every GitLab merge request row ([#13](https://github.com/luongnv89/rex-extensions/issues/13), from [herdr-github#51](https://github.com/luongnv89/herdr-github/issues/51)). The first press only asks: the button turns into **Confirm merge #N** and the notice names the merge method; a second press merges that pull request, and only that one, with `gh pr merge` or `glab mr merge`. Any other key or click, including esc and `q`, takes the question back, and a second press within 0.4 seconds of the first, as in a double click, only keeps the question. On GitHub the method is the repo's: squash when it's allowed, else a merge commit, else rebase; when the repo allows none, or `gh` doesn't say, the press says why and merges nothing. On GitLab the project's own method applies. The merge passes the head commit the list read (`--match-head-commit`, `--sha`), so it's refused when the branch moved since. It never passes `--delete-branch` to `gh` (for the branch a merge deletes, and GitLab's `--remove-source-branch`, see [#39](https://github.com/luongnv89/rex-extensions/issues/39) above); the repo's own setting to delete head branches after a merge, or a merge request's **Delete source branch** box, still applies. The panel then reads the pull request's state: `Merged #N` takes it out of the list, and a refresh already running doesn't bring it back; a merge left waiting in a merge queue or for checks says so and keeps it; a refused merge shows the CLI's reason in red. While the merge runs, the button reads **Merging #N…** and a press on it does nothing; when the pull request stays in the list, refused or waiting, it reads **Merge #N** again ([#20](https://github.com/luongnv89/rex-extensions/issues/20)).
- Agent profiles. A profile has a name, an id, a harness (Claude Code via `mcc run`, Claude Code, Codex, Pi or OpenCode) and an optional model and thinking level; an empty one leaves the harness's own default. Resolve and Review each get their own profile. Models with shell characters or brackets (such as `opus[1m]`) are refused. OpenCode has no thinking flag when it starts, so the panel says it ignores a thinking level.
- A profiles view (`s`, or `⚙` in the header) to add, edit, delete and assign profiles, from the keyboard and the mouse. It reads and writes `~/.config/rex-github/profiles.json`, in herdr-github's format, and never overwrites a change made meanwhile, nor a file it can't read or that holds a profile it can't use.
- Choose the profile when you start Resolve or Review. With one or more profiles of your own, a **Resolve #N** or **Review #N** click, or `a`, opens a menu of every profile, the built-in **Claude Code via mcc run** first, with the action's assigned profile highlighted, under the button clicked (above it when there's no room). Enter or a click starts the one chosen; esc, `q` or a click elsewhere closes the menu and starts nothing. With only the built-in profile, the button starts it right away.
- Custom prompts for Resolve and Review. Each action can send a prompt you write, with `{number}` where the number goes, instead of the IDD skill's; left empty, it sends the skill's prompt as before. The prompt is the last word of the agent's command line, and a custom prompt starts the agent even when the IDD skills aren't installed. Set it in the profiles view's **Resolve prompt** and **Review prompt** rows.
- Pasting types the text into the prompt or the form field being edited, with its line breaks as spaces; nothing pasted is read as a key. In a terminal without bracketed paste, text after the line break that saves the prompt or form is dropped rather than run as commands.
- With mcc, the skills are looked up in the Claude Code folder `mcc env` names for the repo. For mcc, the panel says it opened the pane rather than that Claude Code started, since mcc may first ask something, such as about a usage limit.

### Changed

- The panel keeps the width you drag it to ([#16](https://github.com/luongnv89/rex-extensions/issues/16)). It no longer sets its width back to 36 columns when a pane opens or closes in its tab, and it opens at that width again, also after Rex restarts. The width is kept in `~/.local/state/rex-github/width` on the machine the panel runs on, at most half the panel's split. Resizing Rex's window saves no width. Until you drag it, the panel opens 36 columns wide as before.
- The header no longer shows a Resolve or Review button for the selected row: each row has its own, and `a` still presses the selected row's. The profile menu `a` opened went under the selected row's button, or under the header at its right edge when that button was out of view ([#13](https://github.com/luongnv89/rex-extensions/issues/13)); it now opens at the bottom of the panel, above the key hints ([#28](https://github.com/luongnv89/rex-extensions/issues/28)).
- Resolve and Review open the agent's pane to the right of your agent, side by side (a vertical split), instead of below it.
- The panel is narrower: 36 columns, about the width of Rex's sidebar, instead of a third of the tab. It sets its width again when a pane opens or closes in its tab, since Rex then evens out the tab's splits.

- **Behavior change:** with no profile assigned, Resolve and Review start Claude Code through `mcc run`, instead of the same kind of agent as the one in your tab. Assign a profile to keep using another agent. The panel no longer needs an agent in the tab: with none, the new pane opens beside the pane the panel follows. `pi` now counts as an agent when the panel looks for yours; `gemini` still does, but isn't a harness a profile can start.

### Fixed

- The panel works in a session on a remote host. The action ran `node` with this machine's full path to `panel.js`, which doesn't exist on the remote host, so the pane closed at once. It now passes the path relative to `$HOME`, and the remote host finds `panel.js` under its own `$HOME`: install the extension there at the same path under `$HOME` ([#12](https://github.com/luongnv89/rex-extensions/issues/12)). The pane starts in the folder of the pane it opens beside, or in its machine's default folder when that can't be read, instead of this machine's clone of the extension.

## 0.1.0 (2026-11-05)

### Added

- The panel for Rex, ported from [herdr-github](https://github.com/luongnv89/herdr-github) 0.4.0: the repo's open pull requests (or merge requests) and issues from `gh` or `glab`, in a pane on the right third of the tab.
- `rex-github.lua`: a `github_panel` action for `init.lua` that opens the panel beside the focused pane or closes it. The panel is the block labelled `rex-github`, so nothing is kept on disk to find it again.
- The panel follows the focused pane of its tab through `rex api call`, and reads that pane's folder from its foreground program.
- Resolve and Review find your agent from the foreground program of the panes in the panel's tab (`claude`, `codex`, `gemini`, `opencode`) and start the same agent in a pane below it, with the skill and the number as its first prompt on the command line.
- `install.js`: adds the panel and a key (`cmd+shift+g`, or the first free fallback) to `init.lua`, checks the result with `rex config check`, puts the old file back if the check fails, and reloads the config. `--remove` takes it out again.
